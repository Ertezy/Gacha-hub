# Этап 5 «Фоны и настройки»

## 1. Что делаем

Четыре вещи, выросшие из живой проверки четвёртого этапа:

- **Фоны из магазинов** — у игр из Steam и Epic фон появляется сам.
- **Свой видеофайл как фон** — анимированный фон для любой игры.
- **Вкладка «Вид»** — всё про фоны в одном месте.
- **Переоформление настроек** — крупный текст, понятные вкладки «Поведение» и
  «Данные», пустая панель перестаёт выглядеть сломанной.

**Интерфейс не перекрашивается.** Настройка цвета отменена 13 сентября 2026
(поправка к спеке этапа 4, часть вторая). При смене игры меняется только фон.

**Чего в этой части нет.** Анимированные фоны по умолчанию — §3.6. Арт от
сборщика данных и выбор одной из нескольких картинок магазина — §10.

## 2. Откуда берётся фон

### 2.1. Порядок источников

Первый сработавший выигрывает:

1. **Своё видео** — файл, выбранный человеком на вкладке «Вид».
2. **Своя картинка** — файл, выбранный там же.
3. **Картинка магазина** — если включена галочка «Брать фоны из магазинов» (§3.5).
4. **Заливка** — выводится из названия игры, как сейчас.

Своё важнее магазинного по тому же правилу, что у иконок: это осознанный выбор
человека, и автоматика не имеет права его перекрыть.

Порядок записывается одной чистой функцией, которая по данным игры отвечает,
какой источник показывать. Она проверяется тестами без файлов и без окна.

### 2.2. Какая игра считается установленной из магазина

Игра из Steam — если её способ запуска Steam **или** её файл лежит внутри
папки игры, описанной в манифесте Steam. Так же для Epic.

Второе условие нужно не для полноты, а для живого случая. У владельца
Arknights: Endfield записан как прямой запуск, хотя установлен из Epic: запуск
переключился на прямой, когда владелец указал файл вручную (этап 3). По одному
способу запуска игра осталась бы без фона, хотя магазин её знает.

Игры, добавленные вручную из произвольной папки, картинку магазина не
получают никогда (§5).

## 3. Картинка магазина

### 3.1. Steam: файл уже лежит на диске

Steam хранит картинки библиотеки в `appcache/librarycache` внутри своей папки.
Нужный файл — `library_hero.jpg`, 1920 на 620 точек.

Раскладка кеша встречается двух видов, поддерживаются обе:

- новая: `librarycache/<appid>/<подпапка>/library_hero.jpg` — проверено на
  машине владельца;
- старая: `librarycache/<appid>_library_hero.jpg`.

Если подходящих файлов несколько, берётся самый свежий. Папка Steam ищется уже
существующей `stores::steam::install_roots`.

Файл копируется в кеш фонов **той же функцией** `localcopy::copy_into`, что
иконки и свои картинки: окну разрешено читать только кеш (§2.1 спеки этапа 4,
часть вторая), и второй способ копирования разошёлся бы с первым.

Картинка широкая, а окно приложения намного уже. Она обрезается по бокам и
слегка растягивается. У Wuthering Waves персонаж стоит по центру, для фона
это годится.

### 3.2. Epic: файл скачивается один раз

Epic хранит каталог магазина в `%PROGRAMDATA%\Epic\EpicGamesLauncher\Data\Catalog\catcache.bin`.
Это JSON, записанный в base64. У каждой игры в каталоге есть список картинок;
нужная — тип `DieselGameBox`, 2560 на 1440 точек, ровно пропорции экрана.

Самой картинки на диске нет, только адрес на сервере Epic. Приложение скачивает
её один раз и кладёт в кеш фонов.

Правила чтения:

- файл каталога читается с потолком размера — тот же приём, что у хаба и
  исполняемых файлов;
- base64 разбирается своей функцией: новых зависимостей в проекте не
  добавляется;
- игра находится по идентификатору каталога из способа запуска, а для игр
  по §2.2 — из манифеста Epic;
- **адрес проверяется дважды**: только https и только хост, оканчивающийся на
  `.epicgames.com`. Файл каталога лежит в общей папке, писать туда может любая
  программа, и доверять адресу из него без проверки нельзя.

**Скачивание — одной функцией с кешем картинок хаба.** Сейчас `images::fetch`
умеет безопасно качать: только https, не больше двух переходов и тоже только
по https, потолок размера, запись после проверки пути. Эта часть выносится в
общую функцию с папкой назначения параметром. Картинки хаба и картинки
магазина пользуются ею обе.

Класть картинку магазина в папку картинок хаба нельзя: та чистится по
возрасту, и фон скачивался бы заново каждый месяц.

Потолок размера остаётся прежним, 5 МБ. При реализации картинки четырёх игр
владельца обмеряются; если какая-то не влезает, потолок поднимается с числами
в отчёте, а не на глаз.

### 3.3. Когда добывается

Картинка Steam копируется при построении списка игр, как иконка: это чтение с
диска, миллисекунды.

Картинка Epic требует сети, поэтому **окно её не ждёт.** Когда окно строит
список игр и в нём есть игра Epic без картинки в кеше, недостающие картинки
скачиваются в фоне: при запуске, после добавления игры, после включения
галочки, после очистки кеша. Когда скачивание закончилось, окно получает
событие и перечитывает список игр, не сбрасывая выбранную игру. До этого у
игры видна заливка.

Уже скачанная картинка повторно не качается. Адрес, который не удалось
скачать, до следующего запуска больше не пробуется: без сети каждое построение
списка иначе снова шло бы в сеть. Очистка кеша это забывает. Одновременно
работает одна докачка.

### 3.4. Отказ ничего не ломает

Кеши Steam и Epic не рассчитаны на чужие программы и могут поменять устройство
после обновления магазина. Файла нет, каталог не разбирается, сети нет, сервер
ответил ошибкой — игра получает следующий источник по §2.1, в журнал уходит
одна строка. Приложение работает дальше.

### 3.5. Галочка «Брать фоны из магазинов»

Включена по умолчанию. Выключена — картинки магазина не показываются и не
скачиваются, уже скачанные остаются в кеше до его очистки.

### 3.6. Анимированных фонов по умолчанию нет

Решение §2.4 спеки этапа 4 остаётся в силе: взять их негде. HoYoPlay у
владельца установлен, но хранит фоны упакованными, отдельных файлов картинок и
роликов в его папках нет. Проверено поиском по папкам. Анимация возможна только
из своего файла человека (§6).

## 4. Хранение в конфиге

### 4.1. Поле `video` у игры

```json
{ "video": "D:\\Обои\\genshin.mp4" }
```

Необязательное, читается через `#[serde(default)]`. Стирается пустой строкой в
`update_game`, как `background` и `icon`: `null` при переходе через JSON
неотличим от отсутствующего поля.

### 4.2. Поле `storeArt` верхнего уровня

```json
{ "storeArt": true }
```

**Имя `look` не используется повторно.** Под ним в конфигах людей уже лежит
отменённая настройка цвета. Новая структура под старым именем попыталась бы
разобрать чужие данные.

**Поле обязано читаться в `assemble_current`, `migrate_v1`, `migrate_v2` и
`Default`.** Конфиг текущей версии собирается вручную, поле за полем. Именно
здесь блок `look` едва не подменялся умолчанием при каждом чтении, и это
поймали только на ревью. Поэтому требуется тест прямо на `assemble_current`:
сохранённое `false` остаётся `false`. Тест проверяется мутацией.

### 4.3. Версия конфига не поднимается

Отсутствие поля означает «включено», и после обновления фоны из магазинов
появятся у всех. Это и есть цель обновления. Выбора человека при этом не
теряется: настройки раньше не существовало.

Этим случай отличается от `behaviour` на этапе 3, где отсутствие блока меняло
поведение, которое человек мог настроить.

## 5. Юридические условия

Проверены по первоисточникам 13 сентября 2026. Итог: риск низкий, но не
нулевой. Реальный худший случай — просьба издателя убрать функцию.

Что делает риск низким: приложение ничего не копирует и не раздаёт. Оно
показывает на компьютере человека картинку, которую ему уже доставил Steam или
которую Epic отдаёт открыто. Похожим образом поступают Heroic Games Launcher и
плагины Playnite.

Что найдено неприятного:

- правила Kuro Games для фанатских работ исключают программы, так что
  разрешения на арт Wuthering Waves в приложении нет;
- HoYoverse в деле против сайта HomDGCat возражала даже против опубликованного
  арта, хотя главной претензией были утечки из закрытых тестов;
- условия Epic прочитать не удалось, страница закрыта входом в аккаунт.

**Условия, при нарушении любого из которых риск резко растёт.** Они обязательны
для этой части и для всех следующих:

1. Арт никогда не лежит в репозитории, в сборке и на сервере сборщика.
2. Приложение бесплатное, без рекламы и платных функций.
3. Картинка магазина берётся только для игры, установленной из этого магазина
   (§2.2).
4. Надпись о непричастности к разработчикам игр остаётся на экране.
5. По первой просьбе издателя функция убирается обновлением.

## 6. Свой видеофайл

### 6.1. Что поддерживается

Форматы mp4 и webm. Файл с другим расширением окну не открывается и
считается пропавшим (§6.5). Звука нет, ролик зациклен. На видео нет
медленного дрейфа: ролик и так движется, дрейф поверх него укачивал бы.

### 6.2. Файл не копируется

Картинки копируются в кеш, потому что окну разрешено читать только кеш. Ролик
на сотни мегабайт копировать незачем. Вместо этого окну разрешается читать
**один конкретный файл** там, где он лежит: у Tauri для этого есть
`asset_protocol_scope().allow_file`. Разрешение выдаётся при построении списка
игр и живёт до закрытия приложения.

Проверено по исходникам установленной версии Tauri: протокол отдаёт файл
кусками, без этого видео не проигрывается и не перематывается.

В политику безопасности окна добавляется `media-src` с тем же протоколом, что
у `img-src`. Сейчас видео загружать запрещено.

### 6.3. Пауза, когда окно не видно

Лаунчер живёт в трее часами, и ролик не должен крутиться впустую.

**Окно прячется в двух местах**: крестиком (`lib.rs`) и после запуска игры
(`commands.rs`). Обе точки уже однажды разошлись: защита от окна без значка в
трее стояла в одной и была забыта в другой. Поэтому здесь не добавляется
третья проверка в каждое место. Заводится **одна** функция «спрятать главное
окно»: она проверяет наличие значка в трее, прячет окно и сообщает об этом
странице. Обе точки вызывают её. Показ окна из трея сообщает странице обратное.

Страница ставит ролик на паузу по этому сообщению и по `visibilitychange` —
второе покрывает сворачивание окна.

### 6.4. «Уменьшить движение»

При системной настройке ролик не показывается вовсе. Вместо него — следующий
источник по §2.1: своя картинка, картинка магазина или заливка.

### 6.5. Файл пропал

Игра тихо получает следующий источник. На вкладке «Вид» у игры написано, что
файл видео не найден.

### 6.6. Смена игры

Перетекание между фонами сохраняется для видео так же, как для картинок:
уходящий фон остаётся нижним слоем, пока новый проявляется поверх.

## 7. Экран настроек

### 7.1. Общий вид

Оформление переделывается целиком. Решения:

- **Текст крупнее.** Основной текст 14 точек вместо 12,5. Подписи под
  настройками 13 вместо 12. Заголовок раздела 22 полужирным вместо 15. Вкладки
  слева 15.
- **Карточки вместо голых строк.** Настройки раздела лежат в карточке с фоном
  `--card`, рамкой `--line` и скруглением 12. Строки внутри разделены тонкой
  линией.
- **Строка настройки.** Слева название и под ним пояснение, справа
  переключатель или кнопка. Узкой колонки подписей в 190 точек больше нет,
  поэтому длинные названия не ломаются на две строки.
- **Переключатели вместо стандартных галочек.** Стандартные синие галочки не из
  палитры приложения. Включённый переключатель — цвет действия `--accent`,
  выключенный — `--card` с рамкой.
- **Кнопки и поля** высотой 34 точки, скругление 8, текст 14. Жёлтая кнопка
  только одна на раздел — главное действие.
- **Ширина содержимого** не больше 760 точек, отступы 32 сверху и 40 по бокам.
- **Видимый фокус с клавиатуры** у всех элементов управления.

Все размеры задаются переменными в начале блока стилей настроек, а не числами
по месту: так же сделано у дока.

### 7.2. Вкладка «Игры»

Строки игр в том же оформлении. Из редактора игры **уходит выбор фона**: он
переезжает на «Вид». Название, файл запуска, своя иконка, аргументы запуска и
привязка к контенту остаются.

### 7.3. Вкладка «Вид»

Сверху карточка с переключателем «Брать фоны из магазинов» и пояснением.

Ниже карточка на каждую игру в порядке дока:

- превью текущего фона;
- название и откуда фон: «из Steam», «из Epic Games», «своя картинка»,
  «своё видео», «заливка»;
- кнопки «Картинка…», «Видео…» и «Убрать». «Убрать» стирает своё видео и свою
  картинку, после чего игра возвращается к магазину или заливке.

Превью видео — неподвижный кадр, а не проигрывание: пять роликов сразу на
одном экране грузили бы компьютер.

### 7.4. Вкладка «Поведение»

Одна карточка, две строки с переключателями:

- «Крестик прячет окно в трей» — пояснение: приложение продолжает работать,
  вернуть окно можно из значка в трее;
- «Уходить в трей после запуска игры» — пояснение: окно не мешает игре.

Строка про автозапуск с Windows — приглушённой заметкой под карточкой.

### 7.5. Вкладка «Данные»

Сверху понятная строка. Если данных нет или они из комплекта:

> Коды, баннеры и видео появятся, когда заработает сервис данных.

Иначе — откуда данные и насколько они свежие, теми же словами, что в подвале
панели.

Ниже размер кеша картинок и кнопки «Обновить сейчас» и «Очистить кеш
картинок».

**Поле адреса уходит в свёрнутый блок «Дополнительно»**, как аргументы запуска
у игры. Человеку со стороны вписывать туда нечего, а открытое поле на виду
читается как обязательное.

### 7.6. Вкладка «О программе»

То же содержимое в карточке: версия, кнопки «Репозиторий» и «Показать журнал»,
путь к журналу. Надпись о непричастности к разработчикам — заметкой под
карточкой.

## 8. Пустая панель слева

Файл данных в комплекте сейчас пустой: ни кодов, ни баннеров, ни видео. Все
три секции панели в таком случае ничего не рисуют, и остаётся одна подпись о
давности данных. Это выглядит сломанным.

Когда все три секции пусты, панель показывает одну спокойную строку:

> Пока нет кодов, баннеров и видео. Они появятся, когда заработает сервис
> данных.

Подвал с источником и давностью остаётся.

## 9. Проверка

**Автоматически проверяется:**

- порядок источников фона (§2.1) как чистая функция;
- определение магазина по способу запуска и по манифесту (§2.2);
- поиск картинки Steam в обеих раскладках кеша и выбор самой свежей;
- разбор base64 на опубликованных примерах;
- разбор каталога Epic: поиск игры, выбор типа картинки, отказ на адресе с
  чужим хостом и на http;
- `storeArt` через `assemble_current`: сохранённое `false` остаётся `false`,
  отсутствие поля даёт `true`; проверено мутацией;
- поле `video`: сохранение, чтение и стирание пустой строкой;
- общая функция скачивания: картинки хаба по-прежнему ложатся в свою папку.

**Руками проверяется:**

- у всех пяти игр владельца появился фон магазина, включая Arknights: Endfield;
- выключенная галочка убирает их, включённая возвращает;
- своё видео проигрывается, встаёт на паузу при уходе в трей и при
  сворачивании, продолжается при возврате;
- при «уменьшить движение» вместо видео неподвижный фон;
- настройки читаются крупно и выглядят цельно на всех пяти вкладках.

## 10. Чего в этой части нет

- **Анимированные фоны по умолчанию** — §3.6.
- **Арт от сборщика данных** — поле в схеме хаба заводится, когда сборщик
  сможет его наполнять (§2.3 спеки этапа 4, часть вторая).
- **Выбор одной из нескольких картинок магазина** — берётся одна по правилам
  §3; своя картинка покрывает остальные случаи.
- **Настройка цвета интерфейса** — отменена.
- **Автозапуск с Windows** — за рамками первой версии.
