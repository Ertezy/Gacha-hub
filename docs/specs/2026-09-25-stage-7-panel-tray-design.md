# Этап 7 «Панель и трей»

## 1. Что делаем

Пять вещей, отложенных из этапа 6 (спека этапа 6 §9) и из общей спеки (§12,
«не входит»):

- **Карусель баннеров** — листается сама и плавно, стрелки по бокам картинки.
- **Будущие баннеры** — в той же карусели, после идущих.
- **Автозапуск с Windows** — тихо в трей; вместе с ним защита от второго
  экземпляра и обновление данных, когда появляется сеть.
- **Игры в меню трея** — запуск без открытия окна.
- **Новый README** приложения — по-английски.

Всё новое пишется сразу на двух языках через `src/i18n` (спека этапа 6 §4);
сторож кириллицы не пропустит русскую строку мимо словаря.

## 2. Решения владельца (25 сентября)

| Вопрос | Решение |
|---|---|
| Как часто карусель листает сама | раз в 7 секунд |
| Будущие баннеры | в той же карусели, после идущих, с меткой «Скоро · через …» |
| Автозапуск | тихо в трей, окно не показывается |
| Способ автозапуска | запись в `HKCU\…\Run` через уже подключённый `winreg` (без новых зависимостей) |
| Игры в трее | все игры в порядке дока |
| README | по-английски |

## 3. Карусель и будущие баннеры

### 3.1. Что показывается

- Сначала идущие баннеры — ближайшие к окончанию первыми, затем будущие —
  ближайшие к началу первыми. Отбор и порядок — одна чистая функция в
  `src/lib/panel.ts`.
- На неё же переходит проверка «панели нечего показать» (`panelIsEmpty`):
  игра, у которой есть только будущие баннеры, пустой не считается.
- Правило протухания не меняется: при данных старше недели баннеры — и
  идущие, и будущие — прячутся (общая спека §6).

### 3.2. Карточка

- Идущий баннер — как сейчас: полоса заполнения и остаток времени.
- Будущий — вместо полосы метка «Soon · in 3 days» / «Скоро · через 3 дня»;
  время до начала пишется теми же словами, что остаток у идущих («3 days»,
  «3 h 52 min» / «3 дня», «3 ч 52 мин»).
- Точки-индикаторы снизу: у будущих бледнее, чтобы было видно, где кончаются
  идущие.

### 3.3. Движение

- Все карточки лежат в одной ленте; переход — плавный сдвиг вбок, около
  0,45 с.
- Сама листает раз в **7 секунд**; после последней — к первой.
- Пауза: пока над каруселью мышь, пока в ней фокус клавиатуры, пока окно
  спрятано в трей.
- После ручного листания (стрелка, точка) отсчёт 7 секунд начинается заново.
- Переключатель «Анимация» выключен — карусель сама не листается, а стрелки и
  точки переключают мгновенно, без сдвига.

### 3.4. Стрелки

- Слева и справа, посередине картинки по высоте, круглые, полупрозрачные; при
  наведении — ярче. При одном баннере стрелок нет.
- Работают с клавиатуры; подписи для экранного диктора — из словаря
  (`panel.previousBanner`, `panel.nextBanner`).
- Стрелки из заголовка секции убираются. Комментарий в `Banners.tsx`,
  объясняющий, почему стрелки были в заголовке, заменяется новым: поверх
  картинки их поставил владелец на этапе 7.

## 4. Автозапуск, второй экземпляр, возвращение сети

### 4.1. Переключатель

- Вкладка «Поведение»: «Launch with Windows» / «Запускать вместе с Windows»,
  подсказка — «Starts hidden in the tray and keeps codes and banners fresh.» /
  «Запускается спрятанным в трей и держит коды и баннеры свежими.»
- По умолчанию выключен.
- Включение пишет в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
  значение `Gacha Hub` = `"<полный путь к exe>" --autostart`; выключение
  удаляет его.
- Состояние переключателя читается из реестра, а не из конфига: конфиг не
  меняется, его версия остаётся 3.
- Если значение есть, но указывает на другой exe (приложение переехало), при
  запуске оно переписывается на текущий путь.
- Ограничение: отключение в диспетчере задач («Автозагрузка») Windows хранит
  отдельно (`…\Explorer\StartupApproved\Run`), и переключатель его не видит.
- Сборка для разработки (`tauri dev`) записывает путь к своему exe — после
  проверки автозапуск в ней нужно выключить.

### 4.2. Старт в трей

- С флагом `--autostart` окно не показывается вовсе; значок в трее, данные
  обновляются в фоне.
- Для этого окно создаётся скрытым (`"visible": false` в `tauri.conf.json`) и
  показывается кодом приложения, если флага нет. Плагин восстановления окна
  (`tauri-plugin-window-state`) больше не управляет видимостью — только
  размером и положением.
- Если трей не создался (нет значка), окно показывается и при `--autostart`:
  иначе приложение было бы нечем вернуть.

### 4.3. Второй экземпляр

- Первый экземпляр слушает `127.0.0.1:47631` (порт фиксированный). Второй
  подключается, отправляет приветствие с просьбой показать окно, получает
  ответное приветствие и закрывается; первый показывает своё окно.
- Если порт занят чужой программой (нет правильного ответного приветствия за
  полсекунды), приложение запускается как обычно, без защиты.
- Только петлевой адрес: наружу порт не виден, брандмауэр не спрашивает.
- Без новых зависимостей и без `unsafe` (`std::net`).

### 4.4. Возвращение сети

- Страница слушает событие окна `online`; если с прошлой проверки данных
  прошло больше минуты, данные обновляются сразу.
- Правила этапа 6 (раз в 3 часа, при возвращении окна через час, «побеждает
  последний запрос») не меняются.

## 5. Игры в меню трея

- Меню: все игры в порядке дока, черта, «Show window / Показать окно»,
  «Quit / Выход». Названия игр не переводятся.
- Клик по игре запускает её той же дорогой, что кнопка Play (те же проверки,
  «последняя игра» обновляется); окно остаётся спрятанным.
- Неудачный запуск — окно открывается и показывает ошибку там же, где её
  показывает Play, на выбранном языке (ошибка приходит кодом, спека этапа 6
  §6.2).
- Игра без файла видна, но неактивна, с пометкой «— file not found» /
  «— файл не найден»; пометку переводит словарь трея (`src-tauri/src/i18n.rs`).
- Меню пересобирается при любом изменении списка игр (добавление, удаление,
  порядок, название, находки магазинов) и при смене языка. Пересобирает Rust
  после записи — страница об этом не заботится.
- Шапка `tray.rs` («запуск игр отсюда — не добавлять») заменяется: запуск из
  трея добавлен решением владельца на этапе 7.

## 7. Проверка

### 7.1. Автоматическая

- Карусель: порядок «идущие, потом будущие»; листание по кругу; метка
  «Soon · in …» на обоих языках; `panelIsEmpty` с одними будущими — не пусто.
- Автозапуск: строка запуска и решение «путь переехал — переписать» — чистые
  функции. Тесты в реестр не пишут.
- Второй экземпляр: два «экземпляра» в тесте на свободном порту — второй
  получает ответное приветствие и передаёт просьбу показать окно; чужой ответ
  приветствием не считается.
- Меню трея: список пунктов (названия, неактивные без файла, язык пометки) —
  чистая функция.
- Возвращение сети: правило «больше минуты».
- Сторож кириллицы — как на этапе 6.

### 7.2. Живая проверка владельца

- Карусель листается сама раз в 7 секунд, стоит под мышью, стрелки по бокам
  полупрозрачные; «Анимация» выключена — сама не листается.
- Будущие баннеры — после идущих, с меткой «Скоро · через …».
- Автозапуск: включить, перезагрузить Windows — значок в трее, окна нет,
  данные свежие.
- Второй запуск ярлыком, пока приложение в трее, — открывается то же окно,
  второго значка нет.
- Игра из трея запускается; игра без файла в меню неактивна.
- Выключить автозапуск — значение `Gacha Hub` в реестре исчезает.

## 8. Порядок работы

Один план, для приложения; сборщик не меняется. Задачи: карусель и будущие
баннеры → автозапуск, старт в трей и второй экземпляр → обновление при
появлении сети → игры в трее → README → живая проверка владельца.

## 9. Ограничения

- Ни одной строки `unsafe`, никаких новых зависимостей.
- Конфиг — версия 3 (автозапуск живёт в реестре), схема файла хаба — версия 2.
- Все новые надписи — через словари `en`/`ru`; сторож кириллицы зелёный.
- Комментарии в коде — на русском, сообщения коммитов — на английском, всё от
  имени владельца.
