# Сборщик данных Gacha Hub

## 1. Что делаем

Панель слева показывает промокоды, баннеры и видео пяти игр. Сейчас эти данные
лежат в файле из комплекта, собранном руками 30 августа. Через семь дней
приложение прячет коды и баннеры у всех игр, и панель пустеет.

Этот документ описывает **сборщик**: программу, которая раз в час сама собирает
данные из открытых источников и выкладывает один готовый файл. Приложение
скачивает этот файл. Ручная правка данных перестаёт быть нужной, остаётся
необязательной.

Решение «один сборщик, много читателей» принято ещё в общей спеке (§9) и здесь
не пересматривается: **приложение сайты не читает**. Когда источник меняет
разметку, чинится сборщик одним коммитом, а не выпускается новая версия
приложения.

Решения владельца, на которых стоит документ (15 сентября 2026):

- данные обновляются для всех пользователей, не только для владельца;
- сборщик живёт в отдельном публичном репозитории, код приложения тогда
  оставался приватным (открыт 29 сентября 2026 под MIT);
- в первой версии сразу коды, баннеры и видео по всем пяти играм;
- есть необязательный файл правок;
- о поломке источника владелец узнаёт задачей в репозитории;
- сроки баннеров — по европейскому серверу;
- баннеры Wuthering Waves — с фандома, официальный сайт служит только сигналом.

## 2. Где живёт и из чего состоит

### 2.1. Репозиторий

`https://github.com/Ertezy/Gacha-hub-info`, публичный, ветка `main`. Создан
владельцем.

**Всё в репозитории — от имени владельца.** Коммиты, README, названия
workflow, заголовки и тексты задач, подпись запросов (User-Agent), сам файл
данных. У коммитов один автор — владелец.

### 2.2. Состав

- `src/sources/` — по файлу на источник. Каждый отдаёт записи своей игры и
  своего раздела либо поломку. Источники друг о друге не знают.
- `src/` рядом — слияние, файл правок, проверка итога, задачи, расписание
  источников. Каждая часть — чистые функции, доступ к сети и к GitHub вынесен
  отдельно.
- `catalog.json` — блок `games` файла хаба: известные игры, правила
  сопоставления, адреса погашения. Это наши данные, не собранные; переносится
  из нынешнего файла комплекта.
- `overrides.json` — файл правок (§5.4).
- `test/fixtures/` — сохранённые настоящие ответы источников для тестов.
- `.github/workflows/collect.yml` — сбор; `test.yml` — тесты на каждый коммит.
- `README.md` — что это, откуда данные и под какой лицензией, как править
  файл правок.

### 2.3. Техника

- **Node 24.** Запускает TypeScript сам, без шага сборки.
- **Тесты — встроенный `node:test`.**
- **Зависимостей не больше одной** — разборщик HTML для страниц вики.
  Выбирается в плане: без собственных зависимостей или с минимумом, живой, с
  понятной лицензией.
- Сетевые запросы — встроенный `fetch`.

## 3. Как проходит запуск

Расписание: **в 17 минут каждого часа**. Начало часа у GitHub Actions
перегружено, и запуск там может задержаться или пропасть. Плюс ручной запуск и
запуск при коммите в `overrides.json`.

1. Из кеша GitHub Actions поднимается состояние: прошлый выпущенный файл,
   метки версий ответов, время последней проверки каждого источника, счётчики
   неудач. Кеша нет — прошлый файл берётся с Pages (§5.6).
2. Для каждого источника решается, пора ли его опрашивать (§4.1).
3. Источники опрашиваются: разные сайты одновременно, один сайт — по одному
   запросу за раз. Таймаут, одна повторная попытка с паузой.
4. Удачный источник заменяет записи своей игры и раздела. Сломанный оставляет
   прошлые, без сгоревшего (§5.2).
5. Сверху накладывается файл правок.
6. Итог проверяется целиком (§5.5). Не прошёл — ничего не выкладывается.
7. Файл выкладывается на GitHub Pages, если данные изменились или с прошлой
   выкладки прошло больше 6 часов (§4.4).
8. Задачи приводятся в соответствие с поломками (§5.3).
9. Состояние сохраняется в кеш.

Адрес файла: `https://ertezy.github.io/Gacha-hub-info/hub.json`.

**Данные не коммитятся в репозиторий.** Иначе история пухла бы на копию файла
каждый час.

## 4. Оптимизация

### 4.1. Каждому источнику — своя частота

- Коды и видео — раз в час.
- Баннеры — раз в 6 часов: они меняются раз в три недели.
- Сигнал о новом баннере Wuthering Waves с официального сайта — раз в 6 часов.

Сборщик запускается раз в час, но источник, которому ещё рано, пропускает.

### 4.2. «Изменилось?» вместо скачивания

- Для лент YouTube, ennead.cc и официального списка новостей сборщик хранит
  метку версии ответа (`ETag` или `Last-Modified`) и отправляет условный запрос.
  Не изменилось — ответ пустой.
- Для вики сначала **одним запросом на вики** узнаются номера последних правок
  всех нужных страниц (`action=query&prop=info`). Страница читается целиком,
  только если номер изменился. В тихий час это один маленький запрос на вики.

### 4.3. Вежливость к источникам

- User-Agent: `GachaHubCollector/1.0 (+https://github.com/Ertezy/Gacha-hub-info)`.
- Один сайт — один запрос одновременно.
- ennead.cc — не больше 2 запросов в секунду: это их объявленный лимит.
- Ответ 403, 429 или 503 — одна повторная попытка через паузу, дальше
  поломка. Без повторов в цикле.

### 4.4. Выкладка

- Файл выкладывается, если данные изменились.
- Иначе — не реже раза в 6 часов: `updatedAt` в файле — основа правила
  протухания в приложении (семь дней), и пока сборщик жив, метка не должна
  устаревать.

### 4.5. Размер файла

- JSON без пробелов.
- Сгоревшие коды и закончившиеся баннеры в файл не попадают.
- Видео — по 6 на игру: ровно столько показывает панель.
- Картинки — ссылками на уменьшенные копии шириной 400 точек, как решено в
  спеке этапа 2 (§5): у фандома и wiki.gg свои схемы уменьшенных адресов, их
  знает сборщик.
- Ожидаемый размер — десятки килобайт; потолок приложения 2 МБ.

## 5. Когда что-то идёт не так

### 5.1. Что считается поломкой источника

- **Сеть.** Таймаут, ошибка сервера, блокировка — после одной повторной попытки.
- **Разметка.** Ответ пришёл, но нужного в нём нет: шаблона, таблицы, полей.
- **Подозрительная пустота.** Ноль текущих баннеров или ноль видео у игры —
  поломка. Ноль активных кодов — норма, если сам раздел кодов найден; не
  найден — поломка.
- **Мусор.** Плохие записи выбрасываются поштучно: ссылка не https, конец
  раньше начала, дата старше года, код с пробелами или длиннее 40 символов.
  Выброшено больше половины записей источника — поломка.

### 5.2. Что показывается при поломке

Записи этой игры и раздела из прошлого выпуска. Сгоревшие коды и закончившиеся
баннеры из них всё равно выбрасываются.

### 5.3. Задачи в репозитории

- **Открывается после двух неудачных попыток подряд** — разовый сбой сети
  писем не шлёт.
- Одна открытая задача на источник, метка `источник-сломан`. Заголовок вида
  «Не работает: коды Wuthering Waves (фандом)». В тексте: что сломалось (шаг,
  код ответа, текст ошибки), с какого времени, ссылка на запуск, что сейчас
  показывается («прошлые данные от …»).
- **Пока сломано — меняется только текст задачи** (время последней попытки).
  Правка текста писем не присылает.
- **Заработал — комментарий «Заработал в …» и закрытие.** Сломался снова —
  новая задача.
- Отдельные задачи с той же логикой «одна открытая»:
  - итоговый файл не прошёл проверку;
  - файл правок не читается;
  - новый баннер Wuthering Waves (§6.2);
  - 45 дней без коммита владельца (§5.7).

Решение «открыть, обновить или закрыть» — чистая функция от прошлого состояния
и результатов запуска. Работа с GitHub идёт через встроенный токен запуска.

### 5.4. Файл правок `overrides.json`

```json
{
  "codes": [
    { "game": "endfield", "code": "ENDFIELDGIFT", "rewards": "150 Oroberyl", "expires": "2026-10-01 23:59 UTC+8" }
  ],
  "banners": [
    { "game": "wuthering", "title": "Thousand Futures Mirrored in Snow", "featured": ["Hiyuki"],
      "starts": "2026-09-10 10:00 UTC+1", "ends": "2026-09-29 11:59 UTC+1" }
  ],
  "hide": [
    { "game": "genshin", "code": "WRONGCODE" },
    { "game": "wuthering", "banner": "Название баннера" }
  ]
}
```

- Время пишется строкой с поясом, в число его переводит сборщик. Срок кода
  можно не писать — код бессрочный.
- Код из правок, уже пришедший из источника, не дублируется: награда и срок
  берутся из правки. Баннер из правок сопоставляется с источником по игре и
  названию; когда источник его узнал, побеждает источник.
- Сгоревшее выпадает само, чистить файл не обязательно.
- Коммит в файл запускает сборщик: правка у людей через пару минут. Коммит
  заодно сбрасывает 60-дневный счётчик расписания.
- Файл проверяется тестами на каждом коммите: опечатка видна красным крестиком
  сразу. Если нечитаемый файл всё же попал в запуск, правки пропускаются, сбор
  идёт как обычно, открывается задача.

### 5.5. Проверка перед выкладкой

Итог проверяется по правилам приложения (спека этапа 2, §8): размер, только
https, время числом, начало раньше конца, игры только из каталога, пределы длин
строк. Не прошёл — выложенный файл остаётся прежним, открывается задача.

### 5.6. Если пропал кеш или упал сборщик

- **Кеш пропал** — прошлый файл берётся с Pages; нет и его — сбор с нуля.
- **Упал весь запуск** — GitHub сам пишет владельцу о неудаче. Выложенный файл
  продолжает работать; у людей данные видны до семи дней.

### 5.7. Расписание не должно выключиться

GitHub выключает расписание публичного репозитория после 60 дней без
активности, и коммиты самого запуска от этого, по сообщениям сообщества, не
спасают. Каждый запуск смотрит дату последнего коммита владельца; на 45-й день
открывается задача «сделай любой коммит, иначе через 15 дней расписание
выключится». Хватает правки README с сайта GitHub.

## 6. Источники

Проверены живыми запросами 14–15 сентября 2026. Отчёты: вне репозитория, в
архиве планов (`collector-research-2026-09-14.md`, `-2-2026-09-15.md`,
`-3-wuwa-2026-09-15.md`).

### 6.1. Коды

| Игра | Источник | Срок |
|---|---|---|
| Genshin Impact | фандом, страница `Promotional_Code`, шаблон `Code Row` | UTC; `unknown` и `indef` — без срока |
| Honkai: Star Rail | фандом, `Redemption_Code`, шаблон `Redemption Code Row` | UTC |
| Zenless Zone Zero | фандом, `Redemption_Code` | UTC |
| Wuthering Waves | фандом, таблица кодов | тихоокеанское время, в UTC с учётом летнего времени |

Запасной для трёх игр HoYoverse — ennead.cc `/codes` (слаги `genshin`,

**Коды Endfield автоматически не собираются.** Открытого или официального
источника со сроками нет: официальный сайт, wiki.gg, Fandom и YouTube
проверены. game8.co отвергнут: его условия запрещают автоматический доступ и
перепубликацию.

### 6.2. Баннеры

| Игра | Сроки | Название, персонажи, арт |
|---|---|---|
| Genshin Impact | ennead.cc `/genshin/calendar` | фандом, «Character Event Wish»; файл арта по названию и дате |
| Honkai: Star Rail | ennead.cc `/starrail/calendar` | фандом, «Character Event Warp» / «Light Cone Event Warp» |
| Zenless Zone Zero | ennead.cc `/zenless/calendar` | фандом, страницы баннеров по названию и дате |
| Wuthering Waves | фандом: `Category:Convene` → подстраница `<Название>/<дата>` → шаблон `{{Convene}}` | там же, `imageinfo` за ссылкой на арт |
| Arknights: Endfield | wiki.gg, `Headhunting/Banners` через `prop=text` | там же |

- ennead.cc — открытый проект (`github.com/torikushiii/hoyoverse-api`). Если он
  сломан, сроки баннеров HoYoverse берутся со страниц фандома.
- Название баннера у Star Rail в ennead.cc бывает пустым — название берётся с
  фандома.
- Арт у каждой записи необязателен: не нашёлся — приложение рисует градиент с
  названием (спека этапа 2, §5).
- **Поправка 1 октября 2026 (решение владельца).** Баннер без арта — вики
  назвала файл нового запуска, но ещё не загрузила, или запись взята из анонса
  Kuro — получает самый свежий арт с тем же названием баннера с фандома своей
  игры (`list=allimages` по началу имени; подходят только «Название.ext» и
  «Название ГГГГ-ММ-ДД.ext»). Название баннера закреплено за персонажем, на
  прошлых запусках он тот же. Перепроверка раз в 6 часов; арт текущего запуска,
  когда он появится, побеждает. Endfield не затронут.

**Сигнал о новом баннере Wuthering Waves.** Фандом создаёт страницу нового
баннера через несколько дней после старта. Официальный сайт Kuro публикует
анонс за 1–2 дня до старта, но его условия запрещают воспроизводить содержимое
без письменного согласия. Поэтому:

- сборщик раз в 6 часов читает официальный список новостей
  (`hw-media-cdn-mingchao.kurogame.com/akiwebsite/website2.0/json/G152/en/ArticleMenu.json`)
  и ищет анонсы баннеров;
- если анонс есть, а фандом такого цикла ещё не знает, открывается задача со
  **ссылкой на анонс** и датой публикации — без текста, названий и арта с
  официального сайта;
- владелец вписывает баннер в файл правок; когда появляется страница фандома,
  данные переходят на неё, задача закрывается.

**Поправка 30 сентября 2026 (решение владельца).** Ручные правки на каждый
цикл оказались лишней работой, поэтому сборщик берёт из официального анонса
только факты — название баннера персонажа, имя 5★ резонатора, начало и
конец — и ссылку на сам анонс. Ни текста, ни арта. Начало «с выходом версии»
— конец техработ из патчноута той же версии. Когда фандом узнаёт тот же
баннер, побеждает его запись с артом. Задача владельцу открывается, только
если анонс не разобрался. По первой просьбе Kuro источник убирается.

### 6.4. Время — по европейскому серверу

- **HoYoverse и Wuthering Waves** — Europe, UTC+1.
- **Endfield** — время «AM/EU» из wiki.gg, UTC−5.
- Баннер, стартующий сразу после обновления версии, у всех серверов стартует в
  один момент — окончание обслуживания. Остальные начала и концы идут по
  местному времени сервера.
- **Проверяется при реализации до первого живого запуска:** какой сервер
  отдаёт ennead.cc, и как пишет время фандом Wuthering Waves с пометкой «Server
  Time». Проверка — сравнение двух известных циклов каждой игры с их
  официальными объявлениями. Если источник отдаёт азиатское время (UTC+8),
  серверные моменты сдвигаются на 7 часов позже; момент окончания обслуживания
  не сдвигается.

## 7. Юридические условия

Условия спеки этапа 5 (§5) действуют и здесь: арт не лежит ни в репозитории,
ни в файле, ни на Pages — только ссылки; приложение бесплатное; по первой
просьбе правообладателя источник убирается.

| Источник | Вердикт | Что делаем |
|---|---|---|
| Fandom (CC BY-SA 3.0) | можно с указанием источника | ссылка на страницу у каждой записи |
| wiki.gg (CC BY-SA 4.0) | можно с указанием источника | то же |
| ennead.cc | условий нет, код открыт | ссылка на проект в README |
| YouTube RSS | формально вне официального API, общепринятая практика | если YouTube возразит — переход на Data API v3 |
| game8.co | запрещено | не используется |
| сайт Kuro Games | воспроизведение запрещено | только факты: название баннера, персонаж, сроки — со ссылкой на анонс; без текста и арта; убираем по первой просьбе (решение владельца 30 сентября 2026) |
| трекеры Wuthering Waves | сбор запрещён | не используются |

**Указание источника.** У кода — поле `source` со ссылкой на страницу. У
баннера — поле `url`: страница вики. В README — список источников, их лицензии
и что файл данных распространяется по CC BY-SA 4.0 (лицензия 3.0 совместима с
ней в эту сторону).

## 8. Файл данных

**Схема не меняется** — версия 2 из спеки этапа 2 (§3).

- `updatedAt` — момент выкладки.
- `games` — из `catalog.json`.
- `codes[]`: `gameId`, `code`, `rewards`, `expiresAt` (число или `null`),
  `region` — `"all"`, `source`.
- `banners[]`: `gameId`, `title`, `featured`, `rarity`, `image` (уменьшенный
  адрес или `null`), `startsAt`, `endsAt`, `url`.
- `videos[]`: `gameId`, `title`, `url`, `thumb`, `publishedAt`, `duration` —
  `null`, `premiere` — `false`.

Лишние поля приложение пропускает, но сборщик их не добавляет.

## 9. Что меняется в приложении

1. **Адрес по умолчанию.** Пустое поле «Адрес источника данных» означает адрес
   сборщика. Вписанный свой адрес побеждает. Версия конфига остаётся 3.
2. **Условный запрос.** Рядом с `hub_cache.json` хранится метка версии
   (`ETag`). Ответ «не изменился» — берётся кеш. Цепочка источников, таймаут
   5 секунд, потолок 2 МБ и проверки файла — без изменений.
3. **Обновление в работе.** Раз в 3 часа, и при возвращении окна из трея, если
   с прошлой проверки прошло больше часа. Панель перерисовывается, только когда
   данные изменились.
4. **Файл из комплекта** заменяется свежим файлом со сборщика перед каждым
   выпуском приложения. Это шаг списка выпуска.
5. Правило «старше семи дней — прятать коды и баннеры» остаётся.

## 10. Проверка

### 10.1. Сборщик — тесты на каждом коммите

- Разборщик каждого источника — на сохранённых настоящих ответах, с проверкой
  конкретных значений: код, срок в UTC, начало, конец, ссылка на арт.
- Испорченные ответы: пустое тело, другая разметка, HTML вместо JSON —
  поломка, а не падение.
- Часовые пояса: тихоокеанское время на обеих границах перевода часов, UTC+8 в
  европейское, UTC−5 у Endfield, момент окончания обслуживания без сдвига.
- Слияние: прошлые данные при поломке, сгоревшее выбрасывается, подозрительная
  пустота, больше половины мусора.
- Файл правок: добавление и скрытие кодов и баннеров, совпадение с источником,
  срок строкой, нечитаемый файл.
- Проверка итога: все пределы из §5.5.
- Задачи: две неудачи подряд, закрытие после первой удачи, 45-й день, сигнал о
  новом баннере Wuthering Waves.
- Расписание источников: «пора ли опрашивать».
- Для трёх главных правил — две неудачи подряд, прошлые данные при поломке,
  перевод времени — тест проверяется порчей кода: испорченный код обязан
  уронить тест.
- Режим `--dry-run`: файл пишется локально, Pages и задачи не трогаются.

### 10.2. Первый живой запуск

1. Ручной запуск из вкладки Actions.
2. Файл по адресу Pages: у всех пяти игр видео; коды у Genshin, Star Rail, ZZZ
   и Wuthering Waves; баннеры с датами по европейскому серверу.
3. Задачи: нет, либо по делу.
4. Второй запуск через час: файл не перевыложен, к вики ушли только запросы
   номеров правок.
5. Поломка на пробу: в отдельной ветке испорчен адрес одного источника —
   прошлые данные на месте, задача после второго запуска; починили — задача
   закрылась.

### 10.3. Приложение

- Тесты: пустое поле ведёт на адрес сборщика; метка версии сохраняется и
  отправляется; «не изменился» берёт кеш; обновление раз в 3 часа и при
  возвращении из трея.
- Живая проверка владельца: у всех пяти игр данные «из сети», у Endfield видео
  и баннер; свой адрес побеждает; без сети — кеш.

## 11. Порядок работ

1. Сборщик в `Gacha-hub-info`: тесты, `--dry-run`, первый живой запуск (§10.2).
2. Файл проверяется глазами и через поле адреса в приложении.
3. Правки приложения (§9) отдельной веткой с живой проверкой.
4. Выпуск приложения со свежим файлом комплекта.

Приложение не начинает ходить по адресу, где ещё ничего нет.

## 12. Чего в этой части нет

- **Выбор сервера в приложении.** Сроки баннеров только по европейскому
  серверу; выбор потребовал бы новой схемы файла.
- **Автоматические коды Endfield** — нет открытого источника (§6.1).
- **Фоны из HoYoPlay** — отдельная задача после этого этапа.
- **Арт от сборщика для главного фона** — спека этапа 4, часть вторая, §2.3.
- **Эндгейм-контент и гайды** — общая спека, §12.
- **Автообновление приложения** — общая спека, §12.

## 13. Поправки при планировании

Сверено с живыми ответами источников 15 сентября 2026, когда писался план.

1. **Баннеры HoYoverse — со страниц фандома, ennead.cc — запасной.** Меняет
   §6.2 и §6.4. Страницы баннеров Genshin, Star Rail и ZZZ появляются на фандоме
   за недели до старта и прямо помечают глобальный момент полем
   `time_start_offset` / `time_end_offset`; пустое поле — серверное время.
   ennead.cc не говорит, для какого сервера его числа. Категории: Genshin —
   `Character_Event_Wishes`, Star Rail — `Character_Event_Warps`, ZZZ —
   `Exclusive_Channel_Signal_Searches`; главный персонаж — из шаблона пула.
2. **Только баннеры персонажей**, как в файле комплекта: оружейные не
   собираются.
3. **Подозрительная пустота у баннеров** (§5.1) — ноль разобранных баннеров
   вообще, а не ноль текущих. Иначе Wuthering Waves каждые три недели считался
   бы сломанным, пока фандом не создал страницу нового цикла; этот случай
   закрывает сигнал с официального сайта.
4. **Короткие ролики YouTube остаются** — они есть и в файле комплекта.
5. **Зависимостей во время выполнения нет** (меняет §2.3). Таблица баннеров
   Endfield берётся через `action=expandtemplates` и разбирается по разметке
   шаблона, разборщик HTML не нужен. Для разработки — `typescript` и
   `@types/node`, только проверка типов.
6. **Срок кода датой без времени** действует до конца этого дня по UTC.
7. **Задачи сверяются по метке в тексте**, а не по номерам в состоянии:
   пропажа кеша не плодит дубли.
