# Этап 2 «Видеть» — дизайн

Дополняет [общую спеку лаунчера](2026-08-29-gacha-hub-launcher-design.md).
Общая спека остаётся в силе; здесь разобран второй этап из её §13 и уточнены
места, которые она оставила открытыми.

## 1. Что делает этот этап

После первого этапа лаунчер запускает игры, а панель слева показывает данные
из комплекта — заглушки с надписью «демо». Второй этап наполняет панель живым:
промокоды с таймерами, баннеры с настоящим артом, ролики с превью.

Сборщик данных в этот этап **не входит**. Он отдельный проект со своим планом.
После этого этапа файл хаба обновляется руками; после следующего — сам.
Приложение разницы не заметит: оно и там и там качает один файл.

## 2. Что показывает панель

Три секции сверху вниз, шестерёнка прибита к низу. Отбор в каждой секции свой,
и это не прихоть: у человека может быть пять игр, и если сваливать всё подряд,
получится под тридцать кодов, полтора десятка баннеров и семьдесят пять роликов.

### 2.1. Промокоды — по всем играм

Коды показываются **по всем добавленным играм сразу**, отсортированные по
сгоранию: что горит скорее, то выше. Коды — это список бесплатного, которое
пропадает. Если показывать только выбранную игру, человек прозевает код, потому
что кликает то, во что играет, а не то, где раздают.

Истёкшие коды не показываются вообще, а не сереют.

Карточка кода:

- сам код крупно, моноширинным;
- под ним таймер до сгорания: «сгорит через 3 ч 52 мин», «осталось 9 дней»;
- под таймером — награда одной строкой;
- справа иконка игры, под ней кнопки;
- пометка региона, если код работает не на всех серверах (см. §3.5).

Код без известного срока показывает «бессрочный» вместо таймера.
Код, сгорающий сегодня, выделяется рамкой и цветом таймера.

**Две кнопки, а не одна.** Копировать — всегда. «Забрать» — только если у игры
есть адрес веб-погашения. У ЗЗЗ и геншина есть, у Вувы и Эндфилда нет, коды
вводятся только в игре. Адрес приходит из файла хаба шаблоном, код подставляется
в него; ссылка открывает браузер с уже вписанным кодом.

Клик по карточке целиком копирует код.

Заголовок секции показывает количество активных кодов.

### 2.2. Баннеры — только выбранной игры

Баннер — это «что сейчас идёт вот здесь», поэтому секция следует за **выбранной
на полке игрой**. Переключатель уже есть, новый не нужен: сменил игру на полке —
сменился арт, кнопка PLAY и панель.

Показываются только **идущие сейчас** баннеры. Будущие в данных бывают
(у Эндфилда есть), но в этой версии не показываются.

Карточка баннера:

- сплеш-арт игры, соотношение примерно 16:9;
- поверх арта внизу — имя персонажа и редкость;
- под артом полоса заполнения: сколько прошло от всего срока;
- под полосой название баннера и остаток времени цифрами.

Название баннера **под** полосой, а не поверх арта: на сплеш-арте название уже
нарисовано самой игрой.

Секция — карусель. Стрелки в заголовке секции, а не поверх арта: поверх они
закрывают то, ради чего арт показывают. Точки-индикаторы снизу.

### 2.3. Видео — только выбранной игры

Следует за выбранной игрой, показывает **шесть последних** роликов.

Карточка ролика:

- превью во всю ширину панели;
- под превью заголовок;
- под заголовком иконка игры и когда: «4 дня назад», «вчера».

Значок длительности или слова «премьера» рисуется, **только если данные есть**.
Лента RSS ютуба их не даёт (проверено: в записи только заголовок, ссылка, время
публикации и превью), поэтому оба поля необязательные.

Клик открывает ролик в браузере. Внутри приложения видео не проигрывается.

Место под четвёртую секцию в вёрстке остаётся, но **пустой блок «тут пока
ничего» не рисуется**. Пустота, которую человек видит каждый день, — мусор.

### 2.4. Прокрутка

**Секция кодов получает потолок высоты и прокручивается внутри себя.** Это не
косметика: коды показываются по всем играм сразу (§2.1), а игр у человека может
быть не пять, а двадцать. Без потолка список кодов выдавил бы баннеры и видео
за нижний край, и до них нельзя было бы добраться иначе как долгой прокруткой.

Потолок — примерно три-четыре карточки. Остальные достаются прокруткой внутри
коробки, при этом баннеры и видео остаются на виду.

**Панель сохраняет внешнюю прокрутку** (`.panel-scroll` из первого этапа) как
запасной путь, а шестерёнка остаётся прибитой к низу.

Почему не три независимых области, по одной на секцию: не помещается.
Минимальное окно — 600 точек в высоту (`tauri.conf.json`), за вычетом отступов,
трёх заголовков и шестерёнки на содержимое остаётся около 418. Одна карточка
баннера занимает ~236, одна карточка видео ~235. **Три жёстко заданных секции в
минимальное окно не влезают ни при каком раскладе**, поэтому внешняя прокрутка
нужна, и она включается только когда содержимое действительно не поместилось.

**Прокрутка коробки кодов не сбрасывается при смене игры на полке.** Коды от
выбранной игры не зависят; дёргать список при переключении — значит терять место,
до которого человек долистал.

## 3. Схема файла хаба, версия 2

```json
{

  "updatedAt": 1788091200,

  "games": [

      "title": "Zenless Zone Zero",

      "redeemUrl": "https://zenless.hoyoverse.com/redemption?code={code}",
      "match": {
        "steamAppIds": [],
        "epicAppNames": ["…"],
        "folderNames": ["ZenlessZoneZero"]
      }
    }
  ],

  "codes": [
    {
      "gameId": "zzz",
      "code": "FLINTWORKS",
      "rewards": "300 полихромов, 30 000 денни",
      "expiresAt": 1788105599,

      "source": "https://zenless-zone-zero.fandom.com/wiki/Redemption_Code"
    }
  ],

  "banners": [
    {
      "gameId": "genshin",
      "title": "Ледяная тень лебедя",
      "featured": ["Одетт"],
      "rarity": 5,
      "image": "https://static.wikia.nocookie.net/…/scale-to-width-down/400",
      "startsAt": 1786489200,
      "endsAt": 1788256740,
      "url": "https://www.hoyolab.com/article/46208554"
    }
  ],

  "videos": [
    {
      "gameId": "genshin",
      "title": "Local Legend — Churin",
      "url": "https://www.youtube.com/watch?v=2uJw3z-cYlc",
      "thumb": "https://i3.ytimg.com/vi/2uJw3z-cYlc/hqdefault.jpg",
      "publishedAt": 1787738439,
      "duration": null,
      "premiere": false
    }
  ]

```

### 3.1. Всё время — числом

Каждый момент времени в файле — **unix-секунды целым числом**. Никаких строк
вроде «до 30 сентября».

Это закрывает третий открытый вопрос общей спеки. Сроки кодов и баннеров
привязаны к серверам игр в разных поясах, а показываются человеку в местном
времени. Момент времени однозначен, дата строкой — нет, и на ней таймер соврал
бы на несколько часов.

`expiresAt: null` означает отсутствие известного срока и показывается как
«бессрочный».

### 3.2. Блок `games` — это бывший `catalog.rs`

Сейчас соответствие «установленная игра → идентификатор контента» вшито в код
константами (`catalog.rs`, статический массив `KNOWN`). Оно переезжает в файл
хаба вместе с иконкой игры и адресом погашения.

Смысл переезда: **поддержка шестой игры становится правкой файла, а не выпуском
новой версии приложения.** Ровно то, что обещает §9.2 общей спеки.

`redeemUrl` необязателен. Есть — кнопка «забрать» появляется; нет поля — кнопки
нет. Это не редкий случай: из пяти стартовых игр веб-погашения нет у двух.

### 3.3. Файл из комплекта — пол, а не заглушка

Сейчас в комплекте лежат демо-данные с надписью «замените реальными». Вместо них
кладётся **настоящий снимок**: настоящие коды, баннеры, каталог, арт. Приложение
без сети работает осмысленно.

### 3.4. Каталог читается на старте, содержимое — потом

Панель уже сейчас не ждёт сеть: `App.tsx` вызывает `getHub()` без `await`, и
первый экран рисуется до её ответа. Это сделано в первом этапе и сохраняется.

Ограничение в другом. **Каталог переезжает в файл хаба (§3.2), а сопоставление
установленных игр происходит в `setup()`, до появления окна.** Ходить в сеть
оттуда нельзя: тогда окно начнёт ждать сеть там, где сейчас не ждёт, и мы своими
руками вернём задержку, которой уже нет.

Поэтому разводятся два момента чтения одного файла:

1. **на старте** читается локальная копия — из комплекта или из кеша — и даёт
   каталог для сопоставления установленных игр;
2. **следом, вне критического пути** идёт сетевая загрузка и дорисовывает панель.

### 3.5. Регион носим, но не фильтруем

Часть кодов работает только на азиатских серверах. Пометка региона есть в
источнике и кладётся в файл сразу, потому что достаётся бесплатно.

Отсекать чужие коды можно только зная регион пользователя, а спросить его негде
до третьего этапа с экраном настроек. Пока — маленькая пометка на карточке.

## 4. Источники данных

Проверены живыми запросами 30 августа 2026 года. Приложение к ним **не ходит** —
это работа сборщика. Здесь они записаны, чтобы схема выше была обоснована.

### 4.1. Коды

**Основной — MediaWiki API вики игр.** Единственный источник, дающий срок
сгорания; без него таймер под кодом нечем заполнить.

```
https://zenless-zone-zero.fandom.com/api.php?action=parse&page=Redemption_Code&prop=wikitext&format=json
```

У ЗЗЗ данные лежат шаблоном с полями: код, регион сервера, награда, дата
находки, момент сгорания с поясом. У Вувы та же вики-платформа, но обычная
таблица. **Транспорт единый, разметка разная — по разборщику на вики.**

У Эндфилда страницы кодов на вики нет; для него источник —
`game8.co/games/Arknights-Endfield`, там таблица со сроками.

**Запасные, без сроков:** `hoyo-codes.seria.moe/codes?game=…` и
`api.ennead.cc/mihoyo/…/codes`. Ключи игр: `genshin`, `hkrpg`, `nap`.
Оба покрывают только игры хоёвёрса.

### 4.2. Баннеры

**Хоёвёрс:** `api.ennead.cc/mihoyo/<game>/calendar` — идущие баннеры, персонажи
с редкостью, `start_time` и `end_time` уже unix-числами.

**Эндфилд:** `endfield.wiki.gg/api.php`, страница `Headhunting/Banners`. MediaWiki
1.43.6 с рабочим API. Даёт идущие и будущие баннеры и времена отдельно по
регионам.

**Вува:** `wutheringwaves.fandom.com/api.php`, страницы вида
`<Название баннера>/<дата начала>`. Данные здесь **чище всех остальных**: шаблон
`{{Convene}}` несёт `time_start`, `time_end`, `image`, `link` и `type`
отдельными полями, разбирать нечего.

**Сплеш-арт — вики, имя файла предсказуемо:** «название баннера + дата начала».

```
File:Swan's Shadow in Silken Ice 2026-08-12.png    1200 × 675     (genshin)
File:Paradise Regained 2026-07-29.png              1165 × 622     (zzz)
File:Wind of Transcendence 2026-08-20.jpg          2560 × 1440    (wuthering)
Good_Morning_from_Your_Dawnstar_banner.png                        (endfield)
```

**Расширение файла не угадывается** — у Вувы `.jpg`, у остальных `.png`.
Сборщик обязан брать список картинок страницы и выбирать по имени, а не
достраивать адрес из названия баннера.

**У ХСР арта нет, и это не лень вики.** Страницы баннеров там есть и датированы
как у всех (`Summer Chorus/2026-08-26`, 108 штук), имя файла в разметке
упомянуто по той же конвенции — но самого файла не существует. Проверено на
четырёх баннерах, включая июльские: ссылка красная везде, то есть это не
отставание, а постоянный пробел.

Последствие: **баннеры ХСР показываются градиентом с названием** (§5), сроки и
полоса заполнения при этом настоящие — они приходят от `ennead.cc`, а не от
вики. Поиск другого источника арта для ХСР — задача цикла сборщика, не этого.
На схему и на интерфейс это не влияет: случай «арт не приехал» и так обязателен
к обработке, потому что любая картинка может не скачаться.

### 4.3. Видео

RSS-ленты каналов ютуба, ключи не нужны:

```
https://www.youtube.com/feeds/videos.xml?channel_id=UC…
```

Пятнадцать последних роликов, у каждого заголовок, ссылка, время публикации с
поясом и **адрес превью прямо в ленте**. Идентификатор канала достаётся из
`@хендла`.

## 5. Картинки

**Качает и кеширует Rust, интерфейсу отдаётся путь к локальному файлу.** Иначе
пришлось бы разрешить странице ходить в интернет, а политика безопасности,
закрученная в первом этапе, это запрещает.

Порядок: панель просит картинку по адресу → Rust смотрит в кеше → нет, качает и
кладёт → отдаёт путь.

**Уменьшенный адрес собирает сборщик, а не приложение.** У фандома и у вики.gg
разные схемы адресов для уменьшенных копий. Знание про хосты остаётся в скрипте;
приложение качает что дают. Разница ощутима: арт баннера в оригинале 246 КБ и
2 МБ, уменьшенный до 400 точек — 35 КБ и 173 КБ. Панель шире 400 не бывает.

**Кеш убирается.** Картинка, к которой не обращались тридцать дней, удаляется.
Проверка при запуске. Без этого папка за год превращается в свалку: баннеры
меняются каждые три недели, ролики каждый день.

**Картинка не скачалась — не дырка и не сломанный значок.** Показывается
градиент из `lib/gradient.ts` и название. Выглядит задуманным, а не сломанным.

## 6. Протухание и пустые состояния

Файл несёт `updatedAt`. Приложение сравнивает с текущим временем.

| Возраст данных | Что показывается |
|---|---|
| свежие | всё как есть |
| старше суток | тихая строчка «данные от 28 августа» под шестерёнкой |
| старше недели | **секции кодов и баннеров скрываются целиком** |

Причина последней строки: код, который наверняка сгорел, и баннер, который
наверняка кончился, хуже, чем их отсутствие. Таймер на протухших данных — это
враньё в лицо, и оно заметнее пустоты.

Видео при этом остаются: устаревший список роликов просто устаревший, он никого
не обманывает.

**Секция без данных не рисуется** — не показывает «пусто», а исчезает. Панель
становится короче, а не дырявой. Условие у каждой секции своё, потому что и
отбор у них разный (§2):

- **промокоды** исчезают, когда активных кодов нет **ни по одной** добавленной
  игре;
- **баннеры** и **видео** исчезают, когда их нет **у выбранной** игры.

Второе — обычное дело: у Эндфилда сейчас нет ни одного источника видео, и
выбрав его, человек увидит панель из двух секций вместо трёх. Это нормальный
вид, а не поломка.

## 7. Изменения в коде

**Rust.**

| Файл | Что происходит |
|---|---|
| `hub.rs` (188 строк) | разделяется: схема отдельно, загрузка отдельно |
| `images.rs` | новый: скачать, положить, отдать путь, подмести |
| `catalog.rs` (296 строк) | **худеет**: таблица `KNOWN` уезжает в файл хаба |
| `commands.rs` | новые команды для панели и для картинок |
| `lib.rs` | загрузка хаба уходит с критического пути |

`content_id_for` сохраняет сигнатуру — записка об этом уже лежит в шапке
`catalog.rs` с первого этапа.

**Конфиг не трогается.** Схема пользовательского файла не меняется, миграции
нет, версия остаётся 2. Риска потерять чужие настройки в этом этапе нет.

**Фронтенд.** `SidePanel.tsx` (50 строк) разваливается на три компонента по
секциям плюс оболочку — иначе выйдет файл на четыреста строк.

`styles.css` получает потолок и внутреннюю прокрутку для коробки кодов (§2.4).
Внешняя прокрутка панели и прибитая шестерёнка остаются как есть — они уже
сделаны и работают.

**Форматирование времени выносится в `lib/time.ts` и обкладывается тестами.**
Это единственное место в этапе, где ошибка гарантирована без тестов: русские
числительные зависят от последней цифры, кроме одиннадцати–четырнадцати, где не
зависят. «1 день», «2 дня», «5 дней», «11 дней», «21 день», «111 дней» — все эти
случаи проверяются перебором. Ошибка вылезет не сразу, а на одиннадцатый день, и
будет мозолить глаза на каждой карточке.

**Из отложенных находок первого этапа сюда попадают:** загрузка хаба с
критического пути; ограничение размера ответа для картинок; уборка кеша.

## 8. Безопасность

### 8.1. Файл хаба — недоверенный ввод

**Каждое поле в файле хаба считается враждебным, включая наш собственный файл.**
Это не паранойя, а следствие того, что этап добавляет: приложение начинает брать
произвольные адреса из скачанного файла и писать их содержимое на диск.

Файл может оказаться враждебным тремя путями: подмена по дороге, взлом
репозитория сборщика, и пользователь, сам вписавший чужой `hubUrl` в свой
конфиг. Третий путь не гипотетический — поле открыто для правки.

Отсюда четыре требования, каждое проверяется тестом:

**Имя файла в кеше не выводится из адреса напрямую.** Адрес приходит извне;
если сделать из него путь, подготовленная строка запишет файл за пределы папки
кеша. Имя берётся хешем от адреса, расширение — из типа содержимого, и итоговый
путь обязан остаться внутри папки кеша (проверяется после сборки пути, а не
до).

**Каждый адрес проверяется отдельно перед запросом.** Не «мы же кладём туда
https», а проверка схемы на месте: `https` и только он. `file://`, `http://`,
адреса внутри локальной сети — отказ без запроса.

**Потолок размера соблюдается при чтении, а не по заголовку.** Заголовок
`Content-Length` пишет отправитель, и он может соврать. Чтение обрывается на
пределе (2 МБ для файла хаба, 5 МБ для картинки).

**Код экранируется при подстановке в адрес погашения.** `redeemUrl` — шаблон с
`{code}`. Код приходит из того же недоверенного файла; символ `&` или `#` в нём
меняет смысл ссылки. Подстановка идёт через процентное кодирование, а не
склейкой строк.

### 8.2. Что переносится из первого этапа без послаблений

- только `https`, понижение до `http` запрещено;
- редиректы при загрузке файла хаба запрещены. Проверено:
  `raw.githubusercontent.com` отдаёт файл сразу, без редиректа, — будущий адрес
  хаба с этим запретом совместим;
- при загрузке картинок редиректы разрешены, но не более двух и только внутри
  `https`: картинка декодируется в файл, а не исполняется;
- ограничение размера ответа: для файла хаба 2 МБ, для картинки 5 МБ;
- страница в интернет не ходит; все сетевые запросы делает Rust.

Арт и превью — собственность издателей игр. В интерфейсе показывается строка о
том, что приложение не связано с разработчиками игр, а материалы принадлежат им.
Так делают все фанатские сайты, у которых мы берём данные.

## 9. Что в этот этап не входит

- **Сборщик.** Отдельный проект, отдельный репозиторий, отдельный план.
- **Закрепление игр.** Панель следует за выбранной игрой. Возможность закрепить
  одну или несколько игр — настоящая настройка, ей нужен экран настроек из
  третьего этапа. Устроено так, что потом просто перебивает выбор, а не
  переделывает панель.
- **Фильтр кодов по региону.** Поле носим, фильтруем в третьем этапе.
- **Будущие баннеры.** Данные их местами дают, интерфейс в этой версии
  показывает только идущие.
- **Гайды.** Четвёртая секция, отложена.
