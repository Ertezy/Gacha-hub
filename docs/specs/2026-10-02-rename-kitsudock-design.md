# Kitsudock — переименование Gacha Hub

Дата: 2026-10-02
Статус: согласовано владельцем, готово к написанию плана реализации

---

## 1. Зачем

Имя «Gacha Hub» занято несколько раз: новостной сайт My Gacha Hub, сообщество
в X, YouTube-канал и прототип лаунчера `gachahub` на GitHub (Linux, с
загрузчиком модов). В поиске и в обсуждениях лаунчер путался бы с ними.
Публичного релиза ещё не было — переименовать сейчас почти бесплатно.

Решения владельца (2 октября): имя **Kitsudock** (кицунэ + док с играми, под
иконку-лису; на GitHub проектов с таким именем нет); переименовывается
**всё**, включая служебное; репозиторий сборщика — **Kitsudock-data**;
идентификатор — **`io.github.ertezy.kitsudock`**; настройки со старых
установок **переносятся автоматически**.

## 3. Перенос со старой установки

При запуске Kitsudock, если в новой папке настроек
(`%APPDATA%\io.github.ertezy.kitsudock`) ещё нет `config.json`, а в старой
(`%APPDATA%\com.gachahub.desktop`) он есть, — `config.json`
копируется один раз, до первого чтения конфига.
Старая папка не трогается. Кеши (`%LOCALAPPDATA%`) не переносятся — картинки
и фоны скачаются заново. Свои картинки и видео человека в конфиге записаны
абсолютными путями и остаются рабочими.

Автозапуск: если в `HKCU\…\Run` есть значение старого имени `Gacha Hub`,
Kitsudock удаляет его; если в перенесённых настройках автозапуск был включён,
новое значение `Kitsudock` записывается обычной дорогой (переключатель уже
включён). Так старая программа не стартует с Windows после переименования.

Копирование не удалось — запись в журнал и обычный первый запуск (поиск игр),
без ошибки.

Поправка при планировании: `.window-state.json` не переносится — плагин
положения окна читает его раньше, чем срабатывает перенос; окно один раз
откроется на стандартном месте.

## 4. Порядок выкладки

1. Код с новыми именами и адресами — на ветках, тесты зелёные.
2. Владелец переименовывает оба репозитория на GitHub (Settings → Repository
   name). GitHub перенаправляет старые адреса репозиториев, но не адрес Pages:
   с этого момента старые сборки остаются без свежих данных.
3. Локальные `origin` переводятся на новые адреса, ветки сливаются и пушатся.
4. Владелец запускает сбор данных; проверяется `hub.json` по новому адресу.
5. Владелец удаляет черновик v0.1.0, тег переносится — сборка берёт файл
   данных по новому адресу и выкладывает `Kitsudock-setup.exe`.
6. На ноутбуке: поставить Kitsudock, **не удаляя пока Gacha Hub**, проверить
   перенос настроек, затем удалить Gacha Hub **без** галочки «Удалить данные
   приложения» (или с ней — перенос уже сделан).
7. Публикация.
